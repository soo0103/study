# CDN

- CDN은 Contents Delivery Network의 약어로 콘텐츠 제공자와 사용자가 지리적으로 멀리 떨어져 있는 환경에서 콘텐츠를 빠르게 전달하는 네트워크 기술

## CDN 환경

- CDN 기술이 없는 일반적인 네트워크 통신 환경에서는 원본 콘텐츠를 가지고 있는 오리진(origin) 서버에서 사용자에게 콘텐츠를 전달
    - 오리진 서버에 높은 부하가 발생하고 지리적으로 멀리 떨어져 있는 사용자에게 콘텐츠 전달 시 지연 시간이 길어지는 단점이 존재
- CDN 기술 핵심은 캐시 서버를 지역적으로 분산하고 콘텐츠를 동기화하여 분산 처리하는 것
- 오리진 서버에서 지역적으로 분산된 캐시 서버에 콘텐츠를 동기화해서 콘텐츠가 분산된 환경을 구성
- 사용자는 인접한 캐시 서버로 콘텐츠를 전달받아 빠르고 효율적인 서비스를 제공받을 수 있음
- 높은 성능과 가용성을 보장

## CDN 캐싱 방식

- 오리진 서버의 원본 콘텐츠를 지역적으로 분산된 캐시 서버로 전달하고 콘텐츠를 저장하는 것을 **캐싱**이라 함
- 캐시 서버에 콘텐츠를 가지고 있지 않으면 캐싱 상태를 **Cache Miss(캐시 미스)**라 하고 콘텐츠를 가지고 있으면 캐싱 상태를 **Cache Hit(캐시 히트)**라 함
- 캐시 서버는 콘텐츠를 저장하는 캐싱을 수행할 때 유연하게 관리하고자 일정 시간 동안 콘텐츠를 유지하고 삭제하는 동작을 취함
    
    ⇒ 콘텐츠를 캐싱하는 시간을 **TTL(Time To Live)**이라고 함
    

### Cache Miss

1. 사용자가 캐시 서버에 콘텐츠를 요청
2. 캐시 서버에 해당 콘텐츠가 없어 Cache Miss 판정을 함
3. 캐시 서버는 오리진 서버에 콘텐츠를 요청
4. 오리진 서버는 원본 콘텐츠를 복제하여 캐시 서버에 전달함
5. 캐시 서버는 해당 콘텐츠를 저장하는 캐싱을 수행
    
    ⇒ 정적 캐싱에 해당하는 동작, 동적 캐싱은 콘텐츠를 저장하지 않고 통과
    
6. 캐시 서버는 사용자에게 콘텐츠를 전달

### Cache Hit

1. 사용자가 캐시 서버에 콘텐츠를 요청
2. 캐시 서버에서 해당 콘텐츠를 가지고 있어 Cache Hit 판정을 함
3. 캐시 서버는 사용자에게 콘텐츠를 전달

### 정적 캐싱

- 정적 콘텐츠는 변경되거나 수정되지 않는 콘텐츠
    - 일반적으로 이미지 파일, 자바스크립트, CSS 등
- 정적 캐싱은 정적 콘텐츠를 캐싱하는 방식
- 정적 캐싱은 정적 콘텐츠가 변경되지 않는 특징에 따라 별도의 사용자 요청이 없어도 오리진 서버에서 캐시 서버로 미리 콘텐츠를 복사
    
    ⇒ 사용자가 캐시 서버로 콘텐츠를 요청하면 TTL 동안 바로 응답할 수 있는 Cache Hit 상태로 동작
    
- 정적 캐싱은 CDN의 이점을 살려 효율적으로 전송 가능

### 동적 캐싱

- 동적 콘텐츠는 사용자 요청이나 정보에 따라 즉석에서 생성되는 콘텐츠
    - 사용자 정보를 활용하여 매번 변경되는 형태의 콘텐츠
- 동적 캐싱은 동적 콘텐츠를 캐싱하는 방식
- 동적 캐싱은 동적 콘텐츠가 요청할 때마다 변경이 되는 특징이 있어 캐시 서버에서 콘텐츠를 보관하지 않고 Cache Miss 상태로 동작
    
    ⇒ 캐시 서버는 콘텐츠를 저장하지 않고 통과시키기 때문에 사용자는 오리진 서버에서 캐시 서버를 거쳐 콘텐츠를 전달받음
    
- 동적 캐싱은 캐시 서버에서 동적 콘텐츠를 저장하지 않기 때문에 TTL을 0으로 설정
- CDN 캐싱의 이점을 살리기가 어려움
