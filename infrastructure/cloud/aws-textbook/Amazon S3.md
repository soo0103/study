# Amazon S3

## S3

- Amazon S3(Simple Storage Service)는 AWS 서비스 중 EC2 서비스와 더불어 가장 오래되고 기본이 되는 객체 스토리지 서비스
- S3에 저장되는 데이터를 **객체**라고 하며 객체 저장소를 **버킷**이라 함
- 객체에 대한 입출력은 HTTP 프로토콜로 하며 REST API를 이용해 명령이 전달
- 99.999999999%의 내구성으로 데이터 손실을 최소화하도록 규정
- 특별한 용량 제한 없이 데이터 저장 가능
- 필요한 경우 다양한 스토리지 계층으로 데이터를 분류하여 데이터 저장 비용 절감 가능
- 객체는 기본적으로 웹 접속 가능
    
    ⇒ 정적 웹 콘텐츠를 S3에 올려 웹 서버의 도움 없이 바로 웹 서비스 가능
    
- 보안 규정 준수 및 감시 기능 제공으로 데이터가 안전하게 저장되고 인증된 사용자만 접근할 수 있도록 구성
- 필요 시 접근 권한 정책을 이용해 해당 객체의 접근을 제어

## S3 구성 요소

- Amazon S3는 데이터를 버킷 내 객체로 저장하는 객체 스토리지

### 버킷

- 데이터 스토리지를 위한 S3의 기본 컨테이너(container)
- 객체는 반드시 버킷에 저장되어야 함
- 하나의 리전에서 생성된 후에는 버킷 이름과 리전을 변경할 수 없음

### 객체

- S3에 저장되는 기본 매체
- 객체 데이터와 객체 메타데이터로 구성
- 메타데이터는 객체를 설명하는 이름-값에 대한 하나의 쌍으로 존재
- 객체 저장 시 사용자 정의 메타데이터를 지정할 수 있으며 객체는 키(이름) 및 버전 ID를 이용해 버킷 내에서 고유하게 식별

### 키

- 버킷 내에서 객체의 고유한 식별자
- 버킷 내 모든 객체는 고유한 하나의 키를 갖게 되며 S3는 **버킷 + 키 + 버전**과 객체 사이의 기본 데이터 맵으로 생각할 수 있음

### S3 데이터 일관성

- S3 버킷에 있는 객체에 대해 여러 서버로 데이터를 복제하여 고가용성 및 내구성을 구현하고 데이터 일관성 모델을 제공

## S3 특징

- Amazon S3는 객체에 대해 빠르고 내구성과 가용성이 높은 키 기반의 접근성을 제공하여 데이터의 저장 및 검색에 특화된 객체 스토리지
- S3는 하나의 리전 내 최소 세 개 이상의 물리적으로 분리된 가용 영역에 데이터를 복제해서 저장하므로 높은 내구성과 고가용성을 제공하며 서버의 OS 도움 없이 객체별 접근이 가능하므로 데이터 저장 및 활용에 용이
- 동일 버킷 내 여러 개의 객체 변형을 보유하여 데이터 복구에 특화된 객체 스토리지
- 버전 관리 기능 이용 시 버킷에 저장된 모든 버전의 객체를 보존하거나 검색 및 복원이 가능하며 의도하지 않은 사용자 작업 및 애플리케이션 장애에서 쉽게 복구될 수 있음
- AWS와 다른 서비스를 유기적으로 연동시켜 다양한 형태로 사용 가능
- 뛰어난 내구성으로 빅데이터, 머신러닝을 위한 데이터를 저장하거나 기업의 데이터를 영구적으로 보관하는 등 데이터 보관, 분석에 자주 사용
- 웹 서버의 장치 도움 없이 S3 서비스 객체에 직접 접근 가능
    
    ⇒ 웹 서버의 부하를 줄일 수 있어 서비스 안정성과 성능 향상에 크게 기여
    

## S3 스토리지 클래스

- S3는 여러 사용 사례에 맞게 설계된 다양한 스토리지 클래스를 제공
- **S3 standard**: 자주 접근하는 데이터를 저장
- **S3 intelligent-tiering**: 알 수 없거나 변화하는 접근 패턴이 있는 데이터를 저장
- **S3 standard-IA & S3 one zone-IA**: 데이터 수명은 길지만 자주 접근하지 않는 데이터를 저장
- **S3 glacier**: 데이터 수명이 제한되어 추후 삭제 예정인 데이터 및 백업

### standard

- 가장 일반적인 스토리지 클래스
- 데이터 검색 시 요금 및 최소 사용량에 제한 없이 사용한 만큼 비용 지불

### intelligent-tiering

- 객체 접근 정보가 고정되어 있지 않을 때 자동으로 빈번한 접근 그룹과 간헐적 접근 그룹에 나누어서 저장

### infrequent access

- 객체가 자주 사용되지는 않지만 조회가 필요할 때 사용되는 데이터를 저장하는 클래스
- 두 개의 하위 클래스
    - **standard-infrequent access**: 최소 세 개 이상의 가용 영역에 데이터가 저장되는 내구성이 높은 클래스
    - **one zone-infrequent access**: 하나의 가용 영역에만 데이터가 저장되는 내구성이 낮고 데이터가 삭제되어도 다시 생산할 수 있는 데이터를 위한 클래스

### S3 glacier

- 데이터 아카이브와 장기간 백업을 고려하여 만든 스토리지 클래스
- **아카이빙 데이터**: 오랫동안 데이터가 저장되어 있는 것
- 데이터를 다른 클래스로 옮기려면 비용이 발생하므로 주로 보관이 목적일 때 사용

### S3 glacier deep archive

- 재사용이 거의 없는 데이터를 보관할 때 사용하는 클래스
- 일정 기간이 지나면 삭제할 데이터를 주로 보관
- 조회하는 데 수 시간에서 수 일이 소요될 수 있음
- 데이터 보관 비용이 가장 저렴

## S3 보안

- S3 버킷 접근은 일반적으로 버킷 생성 시 사용한 버킷 이름을 포함하여 생성된 유일한 식별자를 기반으로 언제 어디에서든 접근 가능
- AWS의 자격 증명 서비스인 **IAM(Identify and Access Management)**과 밀접하게 연관되어 있으며 IAM으로 접속 사용자나 데이터 접근을 관리할 수 있음
- IAM으로 사용자 및 정책별 접근 권한을 제어할 수 있으나 접근 권한이 있는 사용자가 개별 객체에 접근할 수 있게 하는 S3만의 버킷 정책으로 S3 버킷 내 모든 객체에 대한 권한을 조정할 수도 있음
