# CloudFormation

- IaC(Infrastructure as Code) 기반으로 AWS 인프라 리소스를 자동으로 생성하는 서비스
- VPC, EC2 등 리소스를 수동으로 생성할 필요 없이 리소스들을 템플릿(코드)으로 구성하고 스택을 생성하여 해당 서비스의 프로비저닝과 설정을 미리 구성할 수 있음
- 인프라를 더욱 빠르게 프로비저닝하고 보안성을 높이고 변경 사항을 추적할 수 있으며, 생성된 템플릿을 재사용하거나 수정해서 활용할 수 있음
- 하지만 모든 AWS 인프라를 정의하고 생성할 수는 없음

## CloudFormation 특징

### **IaC**

- 용어 뜻대로 수동으로 자원을 만들지 않고 선언된 코드로 자원을 생성하는 것
- 불필요한 오류를 줄일 수 있음
- 같은 템플릿 사용 시 다른 환경에서도 인프라를 쉽게 생성할 수 있음
- 변경 사항을 추적하고 변경 내용을 승인하며 이전 버전으로 롤백하는 것이 쉬움

### **AWS 리소스 간 종속성 관리**

- AWS 리소스 간 종속성을 템플릿에 정의할 수 있음
- 종속성을 수동으로 관리하는 것보다 훨씬 쉽고 안정적

### **인프라 관리의 자동화**

- 인프라 구성을 자동화하여 운영 비용을 줄이고 인프라 관리를 간소화할 수 있음
- 지속적 배포를 지원하는 CI/CD 파이프라인과 통합 가능

## CloudFormation 구성 요소

### 템플릿

- AWS 인프라를 JSON 또는 YAML 형식의 코드로 정의하는 파일
- AWS 인프라의 속성, 관계, 종속성 등을 정의

### 스택

- CloudFormation을 이용하여 생성하는 AWS 인프라의 집합

### 리소스

- AWS CloudFormation이 생성하는 AWS 리소스
- Amazon EC2 인스턴스, Amazon RDS 데이터베이스, Amazon S3 버킷 등

### 파라미터

- 스택을 생성할 때 전달할 수 있는 매개변수
- 템플릿을 재사용하여 다른 환경에 대한 스택을 쉽게 생성할 수 있음

### 이벤트

- CloudFormation 스택에서 발생하는 모든 이벤트를 기록
- 이벤트는 스택 생성, 변경, 삭제와 관련된 정보를 제공
- 스택 문제를 해결할 수 있음

### CloudFormation

- 템플릿을 해석해서 스택을 생성하고 정의된 AWS 인프라를 생성, 변경, 삭제할 수 있음

## CloudFormation 동작 순서

### 1. CloudFormation 템플릿 작성

- CloudFormation을 사용하여 관리하고자 하는 인프라를 정의하는 템플릿을 작성
- JSON 또는 YAML 형식으로 작성할 수 있음

### 2. 템플릿 업로드

- 작성한 템플릿을 AWS CloudFormation 서비스에 업로드

### 3. 스택 생성 또는 업데이트

- AWS CloudFormation 서비스를 사용하여 업로드한 템플릿으로 스택을 생성하거나 업데이트
- 템플릿 파일에 정의된 AWS 인프라가 생성되거나 업데이트

### 4. 스택 모니터링

- CloudFormation 서비스는 스택 생성 또는 업데이트를 수행하면서 로그와 이벤트를 생성
- 스택 생성 또는 업데이트 상태를 모니터링할 수 있음

### 5. 스택 삭제

- CloudFormation 서비스에서 스택을 삭제하면 스택에 속한 모든 AWS 인프라도 함께 삭제
