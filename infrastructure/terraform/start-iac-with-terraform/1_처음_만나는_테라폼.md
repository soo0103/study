# 처음 만나는 테라폼

## IaC의 이해

- IaC: 코드형 인프라
- 코드로 인프라를 관리하는 것은 자유롭게 변경하고 환경을 이해하고 반복적으로 동일한 상태를 만들 수 있다는 것
- 좋은 코드의 특징
    - 잘 작동함
    - 읽기 쉬움
    - 모듈화됨
    - 테스트 가능함
    - 보기 좋음
    - 관리가 쉬움
    - 변경이 쉬움
    - 간결함
    - 효율적임
- IaC는 컴퓨터에서 읽을 수 있는 정의 파일을 사용해 인프라나 서비스를 관리하고 프로비저닝하는 프로세스
- 수동 작업이나 지속적으로 변경 사항을 관리할 수 없었던 단점을 극복
- 긍정적인 측면
    - 속도와 효율성
    - 버전 관리
    - 협업
    - 재사용성
    - 기술의 자산화
- 우려되는 측면
    - 코드 문법 학습
    - 파이프라인 통합
    - 대상 인프라에 대한 이해

## 테라폼의 특성

- 테라폼: HashiCorp사에서 공개한 IaC 도구
- 테라폼의 세 가지 철학
    - 워크플로에 집중
    - 코드형 인프라
    - 실용주의
- 테라폼은 `terraform apply` 와 같은 명령으로 구현된 동작으로 만들어진 코드를 실행, 배포
- 테라폼 자체만으로는 인프라와 서비스를 프로비저닝 하는 것은 불가능, 프로바이더가 사이에서 인터페이싱해야 함
- 각 인프라와 서비스는 고유의 API를 가지며 프로바이더는 각 API 명세를 테라폼 코드로 호출해 동작
- 테라폼은 다양한 프로바이더와 조합해 다중 클라우드와 하이브리드 인프라를 지원

## 테라폼 제공 유형

- On-Premise
    - 일반적으로 Terraform이라 불리는 형태
    - 사용자의 컴퓨팅 환경에 오픈소스 바이너리 툴인 테라폼이 구성되며 가장 널리 이용
- Hosted SaaS
    - Terraform Cloud로 불리는 서비스형 소프트웨어로 제공되는 구성 환경
    - HashiCorp가 관리하는 서버 환경이 제공
- Private Install
    - Terraform Enterprise로 불리는 서버 설치형 구성 환경
    - 기업의 사내 정책에 따라 프로비저닝과 관리가 외부 네트워크와 격리되어 이루어지는 환경

| 유형 | 프로비저닝 | 구성 관리 | 프로비저닝 | 프로비저닝 |
| 오픈소스 여부 | 공개 | 공개 | 비공개 | 비공개 |
| 적용 대상 클라우드 | 멀티 | 멀티 | AWS 전용 | Azure 전용 |
| 정책 설정 | 가능 | 불가능 | 부분적 | 부분적 |
| 구성 방식 | 이뮤터블 | 뮤터블 | 이뮤터블 | 이뮤터블 |
| 라이프사이클 관리 | 가능 | 불가능 | 부분적 | 부분적 |

- 테라폼은 특정 클라우드나 인프라에 종속적이지 않고 동일한 워크로드를 설계할 수 있는 것이 장점

## 테라폼 사용 목적과 과제

### 기대 효과

#### 워크플로

- 인프라와 서비스 구성 및 변경 작업인 프로비저닝을 위해 체계화된 워크플로를 제공

#### 자산화

- 테라폼을 통해 프로비저닝 작업에 일관성을 보장, 축적된 프로비저닝 노하우를 자산화 할 수 있음
- 코드 기반의 공유 도구(git, CI, CD 등)들과 통합, 손쉬운 공유와 재사용 가능

#### 표준화

- 작성된 테라폼 코드는 조직 내부의 표준화를 거쳐 모듈화된 상태
- 쉽게 재사용이 가능함
- 내부 정책 및 외부 팀과의 공동 작업을 위한 정책도 정의 가능

#### 프로비저닝 자동화

- 테라폼은 인프라의 변경과 업데이트를 코드 워크플로 도구와 통합 가능
- 테라폼은 작업 수행 전 실행 계획을 작성해 변경 사항을 미리 확인
    
    → 빠른 프로비저닝 수행
    

### 누가 하는가?

- 테라폼은 적용되는 대상 인프라를 알고 새로운 프로젝트가 생겼을 때 설계 및 구축을 담당하는 사람에게 유용함
- 이후 운영, 유지 보수 시 운영을 담당하는 작업자도 테라폼과 관련한 기본적인 지식이 필요

### 인프라의 변경은 더욱 자주 발생할 것

- 자원 효율, 사용자 요구 사항에 따라 인프라는 시간이 지날수록 더 다양한 종류와 특정 목적에 맞는 서비스로 분화
- 인프라의 변경은 앞으로 잦아질 것이며 변화에 적절히 대응할 수 있는지의 여부가 서비스의 지속 가능성을 결정할 것
